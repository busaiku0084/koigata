# 0001. 設計判断を ADR で記録する

- ステータス: 採用
- 日付: 2026-10-11
- 関連: なし

## 背景

個人で開発し、Claude Code にも作業を任せる。半年後の自分や AI が「なぜこうなっているか」を、コードや会話の履歴を掘らずに分かるようにしたい。

## 決定

設計上の判断は `docs/adr/` に 1 判断 1 ファイルで残す。書き方は [README](README.md) に従う。

## 理由

- 判断の理由と、選ばなかった案が残る。同じ議論を繰り返さずに済む
- AI に作業させるとき、守るラインの根拠を渡せる

## 検討した他の案

- README や CLAUDE.md に書き足す: 決定が増えると埋もれ、いつ・なぜ決めたかが残らない
- issue や PR に書くだけ: 後から探しにくい

## 影響

判断を伴う PR には ADR が必要になる（`quality-gate` スキルで確かめる）。
