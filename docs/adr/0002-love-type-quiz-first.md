# 0002. 最初のサービスは恋愛タイプ診断にする

- ステータス: 採用（タイプ数・質問数は [ADR 0008](0008-sixteen-types-with-expression-axis.md) で 16 タイプ・12 問に変更）
- 日付: 2026-10-11
- 関連: [docs/plan.md](../plan.md)

## 背景

「ゲームか恋愛占い系」のサービスを 1 つ作る。条件は、登録不要・X や Instagram に結果をシェアできること・いずれマネタイズすること。

## 決定

- 2 択 9 問で 8 タイプのどれかを出す「恋愛タイプ診断」（仮称: 恋型診断）にする
- タイプは 3 つの軸（自分から動くか・燃え上がるか・いつも一緒にいたいか）の組み合わせで決める
- 結果ページは `/r/<タイプ>` の 8 枚だけで、シェアされるのはこの URL

## 理由

- 「私は○○型」は自己紹介として投稿しやすく、見た人が「自分は？」と診断しに来る。占いの「今日の運勢」より他人に見せたくなる
- 結果が有限なので、シェア画像を事前に作れる（[ADR 0006](0006-pregenerated-share-images.md)）
- 回答をサーバーに送らずに済み、登録不要・個人情報なしで成り立つ
- 集客の仕組み（シェア → 流入 → 診断 → シェア）を先に作れば、後からゲームや別の診断を同じ基盤に載せられる

## 検討した他の案

- ゲーム: 面白さの作り込みに時間がかかり、当たり外れが大きい。まず集客の仕組みを確かめたい
- 名前を入れる相性占い: 他人の名前を入力させることになり、個人情報の扱いが重くなる。結果も無限で画像を事前に作れない
- 日替わりの運勢: 毎日来る理由にはなるが、結果をシェアする動機が弱い

## 影響

- タイプや質問の文言は叩き台。実際の回答の分布を見て直す
- 相性診断（2 人のタイプの組み合わせ）は、ログで完了率とシェア率が見えてから足す
