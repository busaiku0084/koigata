# タイプ・質問の文言とシェア画像の直し方

文言はすべて `src/content/` にある。画面・シェア画像・テストはここから作られる。

## タイプの文言・色を直す

1. `src/content/types.ts` を直す
2. `pnpm gen:images` で `public/og/`・`public/story/` を作り直す
3. 画像を開いて、文字がはみ出していないか見る（とくにストーリーズの下端。キャッチコピーは 19 文字、説明は 18 文字で折り返す）
4. 画像もいっしょにコミットする。忘れると CI が落ちる

`slug` は結果ページの URL（`/r/<slug>`）になる。シェア済みのリンクが切れるので、公開後は変えない。

## 質問を直す・足す

- `src/content/questions.ts` を直す
- 各軸の質問は奇数個にする（同点を作らない）。`pnpm test` で確かめている
- 質問の数を変えたら、トップの「12 問」などの表示は自動で変わる。`pnpm gen:images` でトップの OGP 画像も作り直す

## 文言の決まり

- 結果はエンタメとして書く。断定的な表現（「あなたは〇〇できない」）や、不安をあおる表現は使わない
- 短所は「気をつけたいこと」として、どうすればよいかを添える
- 相性（`bestMatch`）は「動き方と温度が逆、距離感と伝え方が同じ」タイプにする（テストで確かめている）
- 軸そのものを変えるときは ADR を書く（いまの軸の根拠は ADR 0008）

## 別の診断を足すとき

今は 1 つの診断しかない。2 つ目を足すときは、`src/content/` を診断ごとに分け、URL・ログの `result_type` に診断の名前を入れる設計を ADR に書いてから始める。
